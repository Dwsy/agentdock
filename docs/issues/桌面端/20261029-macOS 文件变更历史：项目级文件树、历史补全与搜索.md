# Issue: macOS 文件变更历史：项目级文件树、历史补全与搜索

## Goal

文件编辑/写入/移动历史要完整、可独立查阅（不依赖工具调用记录），文件树按项目分组且不需要逐层展开，历史支持搜索。

## 背景/问题（代码取证）

1. **patch 变更根本不进历史** 🎯：`traceFileChanges` 只会把 `affected_files` 当 `[]string` 解析。实际结构化 patch 返回 `[]{path,operation,move_to}`、unified diff patch 返回 `[]{path,status,binary}`，两种都解析失败 → fallback `payload["path"]`（patch 结果没有该键）→ 历史为空。
2. **move 丢目标**：`file_edit action=move` 返回 `new_path`，结构化 patch 返回 `move_to`，但 `FileChange` 不记录 → 历史只显示「Moved」不知去向。
3. **假变更**：`dry_run`/`changed=false` 的成功调用也进历史。
4. **action 词汇分裂**：replace/add（单文件）vs update/added/deleted/modified（patch/diff）vs Created/Edited（UI），无法筛选。
5. **+/- 行数误导**：多文件 patch 把调用级总数复制到每个文件条目。
6. **文件树难用**：单子链目录要一层层展开（`src/main/java/com/foo` 四级），无项目概念，跨项目变更挤在公共前缀下。
7. **历史查看不独立**：历史是横向 chip，条目信息弱；要读懂改动必须逐个点。

## 关键决策

| 决策 | 理由 |
|------|------|
| 历史采集修在 `traceFileChanges`，不动工具返回契约 | 工具 Schema 是 MCP 契约；历史投影归可观测层 |
| action 归一为 `create/edit/delete/move` | 一套词汇可筛选可映射；UI 文案键随之统一 |
| 项目根 = 路径向上找 `.git`/`go.mod`/`package.json` 等标记，无标记回退父目录 | 与 IDE 项目语义一致，不依赖额外接口 |
| 文件树扁平化渲染（List 行 + 缩进 + 手动展开集） | 保留原生 List 滚动/选中语义，同时支持压缩链与自动展开 |
| 单子链压缩成 `a/b/c` 一行（VS Code compact folders） | 直接消灭「一个一个 cd 进去」 |
| per-file +/- 从 diff 分节统计，截断时是下界 | 多文件 patch 的调用级总数不能冒充单文件统计 |

## 验收标准 (Acceptance Criteria)

- [ ] WHEN `file_edit action=patch`（结构化或 unified diff）成功，历史 SHALL 逐文件记录变更
- [ ] WHEN move（单文件或 patch 内），历史 SHALL 记录源路径与目标路径并显示 `a → b`
- [ ] WHEN `dry_run=true` 或 `changed=false`，历史 SHALL 不产生条目
- [ ] WHEN 多文件 patch，每条历史 SHALL 带按 diff 分节统计的 +/-（截断时如实标注）
- [ ] WHEN 打开 Files 页，树 SHALL 按项目分组（项目根有标记识别，fallback 父目录）
- [ ] WHEN 目录链只有单子目录，SHALL 压缩为一行（`src/main/java`）
- [ ] WHEN 搜索输入，树 SHALL 只保留命中分支并自动展开；命中路径/动作/diff 内容/移动目标
- [ ] WHEN 选中文件，右侧 SHALL 垂直时间线列出全部历史（动作、时间、+/-、目标、截断标记），选中条目渲染 diff，无需打开工具调用
- [ ] `make check`、typecheck、i18n、`go test ./scripts/test` 通过

## 遇到的错误

| 日期 | 错误 | 解决方案 |
|------|------|---------|
| 2026-10-29 | diff 分节统计与受影响文件路径形态不一致（相对 vs 展示路径） | `lookupDiffStats` 先精确后按 `/` 后缀对齐 |
