# Issue: 调用来源 User-Agent 记录、持久化与展示

## Goal

每条工具调用记录调用来源客户端的 `User-Agent`：进入 Analytics 最近调用、trace 记录与磁盘 JSONL，并在控制面板 Activity / Traces 中显示与搜索。

## 背景/问题

`Source` 只能区分 `mcp` / `nexus` / `internal`，无法区分同为 MCP 的 ChatGPT、Claude、Codex、脚本或桌面端。排障时经常需要知道「这条调用是谁发起的」，而 UA 是唯一稳定可得的客户端标识。

## 验收标准 (Acceptance Criteria)

- [x] WHEN 通过 HTTP MCP 调用工具，`User-Agent` SHALL 记录到 Analytics 与 trace
- [x] WHEN 调用来自 Nexus Bridge，SHALL 标记 `nexus-bridge`；stdio SHALL 标记 `stdio`
- [x] WHEN `disk` 模式重启，UA SHALL 从 JSONL 恢复
- [x] WHEN 在 Traces 搜索 UA 片段，SHALL 命中
- [x] WHEN UA 超长或含控制字符，SHALL 清洗并截断到 256 字节且保持 UTF-8 边界
- [x] WHERE Activity / Traces，SHALL 显示 UA（单行截断，悬停看完整值）
- [x] WHERE Nexus 远程诊断契约，SHALL 不扩大字段（UA 仅在本地可见）

## 关键决策

| 决策 | 理由 |
|------|------|
| UA 存 context 而非扩 `EndTool` 之外的 API | 与 `Source` 同一条传递路径，调用点最少 |
| 截断 256 字节并清洗控制字符 | UA 可能很长或含换行，直接写盘会污染 JSONL/日志 |
| 空 UA 不写入 | UI 不需要显示空字段，也不会产生无意义差异 |
| 不进入远程诊断投影 | UA 可能包含设备/版本信息，Nexus 侧无排障需求 |
