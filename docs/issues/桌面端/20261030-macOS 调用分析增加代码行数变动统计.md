# Issue: macOS 调用分析增加代码行数变动统计

## Goal

在 macOS 调用分析页展示代码行数变动：新增行数、删除行数（总量与按工具拆分）。

## 背景/问题

调用分析页只有调用次数、错误与延迟分位，看不出 Agent 到底改了多少代码。行数变动数据其实已经存在：`file_edit` 的返回结果带 `insertions` / `deletions`，文件历史（`/internal/runtime/file-changes`）也按文件展示 `+/-`，但只有"文件数"页能看到，分析页没有任何聚合。

## 验收标准 (Acceptance Criteria)

- [x] WHEN Core 健康，页面 SHALL 展示新增行数与删除行数两个指标卡
- [x] WHEN 存在 tool_stats，明细表 SHALL 展示每个工具的新增/删除行数列
- [x] WHEN 一次 file_edit 成功，analytics SHALL 计入该次调用的增删行数
- [x] IF trace 关闭，THEN 代码行数统计依然成立（不依赖 trace 采集）
- [x] IF 调用失败或 dry_run，THEN 不计入行数变动
- [x] WHERE Windows / Linux 桌面端，系统 SHALL 无行为变化

## 实施阶段

### Phase 1: 规划和准备
- [x] 确认行数来源：file_edit 结果的 `insertions` / `deletions`
- [x] 确认聚合口径：recorder（调用分析的唯一数据源），不从 trace store 二次统计

## 关键决策

| 决策 | 理由 |
|------|------|
| 统计挂在 recorder 而不是 trace store | 调用分析页的其他数字都来自 recorder；trace 关闭时分析页仍要有数据 |
| `EndTool` 改收 `CallMeta` 结构体 | 位置参数已 12 个，再加两个 int 极易传错 |
| 总量用进程启动以来累计 | 与 `total_calls` / `total_errors` 同口径，窗口内的按工具拆分补足时间维度 |
| 只统计 `file_edit` | 当前只有文件编辑类调用有增删行数语义 |
