# 降低追踪文本搜索延迟

状态：✅ 已完成

## 目标

减少调用追踪搜索对长文本的扫描成本，保留原有匹配结果和写入路径的脱敏行为。

## 基线与范围

当前 AgentDock 工作树 HEAD 为 `7aad008`。现有 `BenchmarkTraceStoreQuerySearch` 在 Apple M3 Max、Go 1.27.4、`-cpu=1` 下搜索 2,000 条记录，未命中耗时 8.37–8.39 ms/op，每次分配 16,384 B。`containsFold` 同时用于追踪、脱敏预筛和网络抓包搜索。只修改该匹配函数及其定向验证。生产代码有在途改动，先在 `bin/.rsi-mwu50r413sm2q0pko1l` 的隔离工作树实施，复核后按独立补丁落回当前工作树。

## 验收

- [x] 同一机器、同一数据和 Go 版本下，现有搜索基准的多次运行中位数至少降低 30%，每次分配次数与字节数不增加。
- [x] 定向回归覆盖大小写、标点、Unicode 及不合法 UTF-8。追踪查询的过滤、分页、脱敏行为通过现有 Go 测试。
- [x] 对照记录生成和脱敏路径的已有基准检查有无明显回退，记录前后实测结果。
- [x] 核对最终补丁只包含上述允许路径，现有工作树改动保留。

## 回滚

反向应用本轮独立补丁。无需迁移追踪数据、调整运行配置或重启服务。
