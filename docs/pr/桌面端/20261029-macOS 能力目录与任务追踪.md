# macOS 控制面板：能力目录、任务矩阵与调用追踪

> 在 macOS 原生控制面板左侧直接看到本机全部 MCP Tool / Skill / AGENTS.md / Plugin，并把 GAPP 任务矩阵与可开关的调用追踪搬进同一个窗口。Windows、Linux 与既有页面行为不变。

## 背景与目的 (Why)

控制面板此前只有 5 个固定页面，`Capabilities` 仅做开关配置。模型实际可用的工具定义、全局 Skill、扫描到的规则文件和插件元数据只能通过 MCP 或命令行获取；任务状态只能打开 GAPP 查看；调用排障看不到入参出参。本次把这三类「本机到底提供了什么、正在发生什么」的信息收敛到控制面板。

## 变更内容概述 (What)

### 后端（只读新增，不改变既有契约）

- 新增 `GET /internal/runtime/catalog`：返回当前配置下全部工具定义（`name`/`title`/`description`/`input_schema`/`output_schema`/`annotations`）+ 本次扫描到的 `AGENTS.md`（scope/path/status/content/sha256/size）。
- 新增 `GET /internal/runtime/traces?q=&tool=&source=&status=&limit=`：返回 trace 记录、状态与已出现工具名。
- 新增 `observability.TraceStore`：`off`/`memory`/`disk` 三档；内存环形索引 + 按天 JSONL 批量追加；启动回放保留窗口、过期文件清理；每侧 8 KiB 截断 + 通用/JSON 键值脱敏。
- `Runtime.Call` 统一采集点接入 trace；默认 `off` 时不产生序列化开销。
- 任务列表项补 `project`、`device`（分组与搜索所需的最小字段）。
- 配置项：`AGENTDOCK_TRACE_MODE`、`AGENTDOCK_TRACE_RETENTION_DAYS`（1–30）、`AGENTDOCK_TRACE_BUFFER_SIZE`、`AGENTDOCK_TRACE_FLUSH_MS`、`AGENTDOCK_TRACE_MAX_RECORDS`。

### macOS UI

- 侧栏改为统一 `SidebarSelection`：页面导航 + Tools / Skills / Rules / Plugins 四个分组，条目直接列出。
- 详情页：工具 Schema（格式化 JSON、可选中）、Skill 元数据、规则正文、插件元数据。
- 新增 `Tasks` 页面：状态筛选、关键字搜索、按项目折叠分组、步骤进度、详情下钻；时间精确到分，悬停显示秒。
- 新增 `Traces` 页面：模式/保留期状态、关键字搜索、工具与状态筛选、入参/出参/错误详情。
- 新增 `Analytics` 页面：窗口/累计调用、错误率、进行中调用；工具调用次数条形图 + 明细表，支持搜索与按次数/错误率/P95 排序，5 秒轮询。
- 目录数据 20 秒节流刷新；新增 59 条中英文文案。

## 风险与影响评估 (Risk Assessment)

| 风险 | 说明 | 缓解 |
|------|------|------|
| trace 泄露凭据 | 入参可能含 token | 默认关闭；两侧 8 KiB 截断；通用 + JSON 键值脱敏 |
| trace 写盘放大 | 大结果或图片 base64 | 截断后写入；批量 flush；保留天数上限 30 |
| 侧栏过长 | 32 工具 + Skill + 规则 + 插件 | 分组标题带计数，List 原生滚动 |
| 任务列表字段扩展 | `project`/`device` 进入 Runtime API | 纯新增字段，向后兼容 |
| Swift 类型未本机验证 | 缺 Xcode 宏插件 | 已通过语法解析；依赖 macOS CI 编译 |
| 统计口径 | 仪表盘复用 `/analytics`，与 Activity 同源 | 单一数据源，不新增统计逻辑 |

## 回滚计划
