# Issue: macOS 控制面板左侧能力目录（Tool / Skill / AGENTS.md / Plugin）

## Goal

macOS 原生控制面板左侧导航直接列出本机全部 MCP Tool（含描述、入参、出参）、全局 Skill、可扫描到的 `AGENTS.md`、已安装 Plugin；点击条目在右侧查看完整定义。Windows / Linux 与既有页面保持不变。

## 背景/问题

左侧目前只有 5 个固定页面（Home / Connections / Capabilities / Activity / Settings），`Capabilities` 仅是 browser / ACP / MCP Apps 的开关配置。运行时真正暴露给模型的 32 个工具、Skill 索引、规则文件和插件元数据只能通过 MCP 工具或命令行获取，桌面上无法自查「本机到底提供了什么能力」。

`/internal/runtime/status` 只返回工具名数组，没有 schema；`/internal/runtime/skills`、`/internal/runtime/plugins` 已有索引，可直接复用。

## 验收标准 (Acceptance Criteria)

- [ ] WHEN Core 健康，左侧 SHALL 列出全部可用 Tool，条目数等于 Sidebar 计数
- [ ] WHEN 选中某个 Tool，右侧 SHALL 展示 name、title、description、input_schema、output_schema、annotations
- [ ] WHERE Skill 分组，系统 SHALL 列出 managed Skill；点击后展示 source_type、skill_ref、content_digest、描述
- [ ] WHERE Rules 分组，系统 SHALL 列出本次扫描到的 `AGENTS.md`（全局 + 默认工作目录），点击展示 path、status、size、正文
- [ ] WHERE Plugins 分组，系统 SHALL 复用已有 inspect 信息展示 version、format、provenance、skill/mcp 数量
- [ ] IF Core 未运行或请求失败，THEN 分组显示不可用占位，主页面不崩溃、不阻塞
- [ ] WHERE Windows / Linux 控制面板，系统 SHALL 无行为变化

## 关键决策

| 决策 | 理由 |
|------|------|
| 新增 `GET /internal/runtime/catalog`，而不是扩展 `/status` | `/status` 是 Nexus 与 CLI 共用的稳定轻量契约；塞入全量 schema 会让每次健康检查都传输 32 份 JSON Schema |
| catalog 用可选接口 `CatalogRuntime` | 与 `DiagnosticsRuntime` 一致，旧测试替身无需实现空方法；不支持时明确返回 `CATALOG_UNSUPPORTED` |
| skills / plugins 复用现有端点 | 已有索引与 inspect 语义，避免第二套数据投影漂移 |
| Sidebar 用 `Section` + 统一 selection enum | SwiftUI 原生分组；`List(selection:)` 只接受单一类型，必须把页面与条目收敛到一个枚举 |
| Schema 只读展示格式化 JSON | 控制面板不是编辑器；避免引入可写 JSON 带来的校验与保存语义 |

## Notes

- `Runtime.ToolDefinitions()` 已按当前 `config` 生成 capability-aware schema，直接复用即可，不能调用 `app.ToolDefinitions()` 全局函数（那份用空配置）。
- `agentinstructions.Load` 每次重新读盘，不做 mtime 缓存；catalog 端点因此也按请求实时读取。
- 规则扫描根与 `workspace_context` 保持一致：`~/.agentdock` + workspace root，GUI 以 AgentDock 默认工作目录作为 workdir。
